## ⚡ 3-Layer Clean Architecture Specifications

Every feature must be strictly divided into **Domain**, **Data**, and **Presentation**:

### 1. Domain Layer (`features/<feature>/domain/`)
- **Zero dependencies on Flutter UI or external packages** (except `equatable`, `either.dart`, and `typedef.dart`).
- **Entities**: Business objects extending `Equatable`.
  ```dart
  class UserEntity extends Equatable {
    const UserEntity({required this.id, required this.name, required this.email});
    final String id;
    final String name;
    final String email;

    @override
    List<Object?> get props => [id, name, email];
  }
  ```
- **Repositories (Contracts)**: Abstract interfaces returning `ResultFuture<T>`:
  ```dart
  abstract class AuthRepo {
    ResultFuture<UserEntity> login({required String email, required String password});
    ResultFuture<void> logout();
  }
  ```
- **UseCases**: Discrete call classes:
  ```dart
  @lazySingleton
  class LoginUseCase {
    final AuthRepo _repo;
    LoginUseCase(this._repo);

    ResultFuture<UserEntity> call({required String email, required String password}) {
      return _repo.login(email: email, password: password);
    }
  }
  ```

### 2. Data Layer (`features/<feature>/data/`)
- **DataSources**: Retrofit interface with Dio:
  ```dart
  @RestApi()
  abstract class AuthDataSource {
    factory AuthDataSource(Dio dio) = _AuthDataSource;

    @POST('/auth/login')
    Future<ApiResponse<UserModel>> login(@Body() Map<String, dynamic> body);
  }
  ```
- **Models**: `@JsonSerializable(explicitToJson: true)` with manual `copyWith` and Model-to-Entity mappers:
  ```dart
  @JsonSerializable(explicitToJson: true)
  class UserModel {
    final String? id;
    final String? name;
    final String? email;

    UserModel({this.id, this.name, this.email});

    factory UserModel.fromJson(Map<String, dynamic> json) => _$UserModelFromJson(json);
    Map<String, dynamic> toJson() => _$UserModelToJson(this);

    UserModel copyWith({String? id, String? name, String? email}) {
      return UserModel(
        id: id ?? this.id,
        name: name ?? this.name,
        email: email ?? this.email,
      );
    }

    UserEntity toEntity() => UserEntity(
      id: id ?? '',
      name: name ?? '',
      email: email ?? '',
    );
  }
  ```
- **Repository Implementations**: Decorated with `@LazySingleton(as: <Interface>)` and wraps try/catch into `Right(data)` or `Left(ApiErrorHandler.handle(e))`:
  ```dart
  @LazySingleton(as: AuthRepo)
  class AuthRepoImpl implements AuthRepo {
    final AuthDataSource _dataSource;
    AuthRepoImpl(this._dataSource);

    @override
    ResultFuture<UserEntity> login({required String email, required String password}) async {
      try {
        final response = await _dataSource.login({'email': email, 'password': password});
        return Right(response.data!.toEntity());
      } catch (e) {
        return Left(ApiErrorHandler.handle(e));
      }
    }
  }
  ```

### 3. Presentation Layer (`features/<feature>/presentation/`)
- **State Management**: **Cubit ONLY** with **Freezed States**.
  ```dart
  @freezed
  class AuthState with _$AuthState {
    const factory AuthState.initial() = _Initial;
    const factory AuthState.loading() = _Loading;
    const factory AuthState.success(UserEntity user) = _Success;
    const factory AuthState.error(String message) = _Error;
  }

  @injectable
  class AuthCubit extends Cubit<AuthState> {
    final LoginUseCase _loginUseCase;
    AuthCubit(this._loginUseCase) : super(const AuthState.initial());

    Future<void> login(String email, String password) async {
      emit(const AuthState.loading());
      final result = await _loginUseCase(email: email, password: password);
      result.fold(
        onLeft: (error) => emit(AuthState.error(error.message ?? 'Unknown error')),
        onRight: (user) => emit(AuthState.success(user)),
      );
    }
  }
  ```
- **Screens & Widgets**:
  - STRICT: **ONE WIDGET CLASS PER FILE**. No function widgets.
  - Platform-adaptive and responsive.

## 🌐 Enterprise Network Subsystem (`core/network/`)

Follows a robust, production-grade network pattern:


1. **`ApiErrorHandler`**:
   - Inspects `DioExceptionType` (`connectionTimeout`, `sendTimeout`, `receiveTimeout`, `badResponse`, `cancel`, `connectionError`, `unknown`).
   - Extracts server error message, error code, and status code into `ApiErrorModel`.
2. **`AuthInterceptor`**:
   - Injects `Bearer <token>` on all requests.
   - On `401 Unauthorized`:
     - Locks simultaneous requests using `Completer<String?>? _refreshCompleter`.
     - Calls `/auth/refresh` on a separate non-intercepted `_refreshDio` instance.
     - Saves new tokens to `TokenStorage`.
     - Retries original queued requests with the new access token.
     - Clears tokens and triggers logout if refresh token expired.
3. **`ApiResponse<T>` & `PaginatedResponse<T>`**:
   - Strongly-typed response wrappers with `@JsonSerializable(genericArgumentFactories: true)`.
4. **`either.dart` & `typedef.dart`**:
   - `typedef ResultFuture<T> = Future<Either<ApiErrorModel, T>>;`
   - `typedef DataMap = Map<String, dynamic>;`

## 💉 Dependency Injection with `Injectable` + `GetIt`

1. **Setup in `lib/core/config/service_locator.dart`**:
   ```dart
   final getIt = GetIt.instance;

   @InjectableInit(
     initializerName: 'init',
     preferRelativeImports: true,
     asExtension: true,
   )
   void configureDependencies(EnvConfig envConfig) {
     getIt.registerSingleton<EnvConfig>(envConfig);
     getIt.init();
   }
   ```
2. **Registering 3rd Party Modules (`core/services/register_module.dart`)**:
   ```dart
   @module
   abstract class RegisterModule {
     @lazySingleton
     Dio getDio(AppConfig config, AuthInterceptor authInterceptor) =>
         DioClient.createDio(config, authInterceptor);

     @preResolve
     Future<SharedPreferences> get sharedPreferences => SharedPreferences.getInstance();

     @lazySingleton
     FlutterSecureStorage get secureStorage => const FlutterSecureStorage();
   }
   ```
3. **Annotations**:
   - `@singleton` for config facades (`AppConfig`).
   - `@LazySingleton(as: RepoInterface)` for repositories.
   - `@lazySingleton` for UseCases and DataSources.
   - `@injectable` for Cubits and Interceptors.

## 🚩 Mandatory Multi-Environment Flavors

Every project **MUST** have Flavors configured out-of-the-box:

1. **`AppFlavor` Enum**:
   - Contains: `dev`, `staging`, `production`.
   - UI Properties: `displayName`, `titleSuffix`, `appTitle`, `color`, `backgroundColor`, `icon`, `isDev`, `isStaging`, `isProduction`.
2. **`EnvConfig` Abstraction**:
   - Properties: `baseUrl`, `apiKey`, `flavor`, `enableLogging`, etc.
3. **Concrete Configs**:
   - `DevConfig`, `StagingConfig`, `ProductionConfig` reading from `.env.dev`, `.env.staging`, `.env.production`.
4. **Entry Points**:
   - `main_dev.dart` -> `await dotenv.load(fileName: '.env.dev'); await bootstrap(EnvConfigFactory.create(AppFlavor.dev));`
   - `main_staging.dart` -> `await dotenv.load(fileName: '.env.staging'); await bootstrap(EnvConfigFactory.create(AppFlavor.staging));`
   - `main_production.dart` -> `await dotenv.load(fileName: '.env.production'); await bootstrap(EnvConfigFactory.create(AppFlavor.production));`
5. **Flavor Banner**:
   - Automatic visual ribbon on non-production builds (`main.dart` builder).

## 🌍 Mandatory AR/EN Localization (Zero Hardcoded Strings!)

1. **Rule**: **NO HARDCODED STRINGS IN UI OR ERROR MESSAGES**.
2. **Setup**:
   - `l10n.yaml` configured with `arb-dir: lib/l10n`, `template-arb-file: intl_en.arb`, `output-localization-file: app_localizations.dart`.
   - `lib/l10n/intl_en.arb` (English).
   - `lib/l10n/intl_ar.arb` (Arabic - RTL support).
3. **Usage via Extension**:
   ```dart
   // In core/extension/context_extension.dart
   extension BuildContextExt on BuildContext {
     AppLocalizations get l10n => AppLocalizations.of(this)!;
     bool get isArabic => Localizations.localeOf(this).languageCode == 'ar';
   }
   ```
4. All Buttons, Titles, Hints, Validators, Error Messages, and Statuses must read from `context.l10n.<key>`.

## 🛡️ Coding Standards: Validation, Caching & Errors

### 1. Enterprise Validation Rules (`core/utils/validators.dart`)
- Centralized static/composable validators:
  - `Validators.validateEmail(String? value, BuildContext context)`
  - `Validators.validatePassword(String? value, BuildContext context)` (min 8 chars, 1 uppercase, 1 digit, 1 special)
  - `Validators.validatePhone(String? value, BuildContext context)`
  - `Validators.validateRequired(String? value, String fieldName, BuildContext context)`
- All validator messages MUST return localized strings from `context.l10n`.

### 2. Caching & Offline Storage
- **Tokens & Credentials**: `FlutterSecureStorage` via `TokenStorage`.
- **User Preferences & Session**: `SharedPreferences`.
- **Cache-First Pattern in Repositories**:
  ```dart
  // 1. Check local cache / memory
  // 2. If valid and not expired -> return Right(cachedData)
  // 3. Else fetch from Remote DataSource -> save to cache -> return Right(remoteData)
  // 4. If remote fails and cache exists -> return Right(staleCachedData) with offline warning
  ```

### 3. Error Handling Architecture
- **Infrastructure / DataSource**: Throws `ServerException(message, statusCode)` or `DioException`.
- **Data Repositories**: Catch all exceptions and map via `ApiErrorHandler.handle(e)` into `Left(ApiErrorModel)`.
- **Domain UseCases & Logic**: Operate cleanly on `ResultFuture<T>` with zero unhandled crash risks.
- **Presentation**: `result.fold(onLeft: (err) => emit(Error(err.message)), onRight: (data) => emit(Success(data)))`.
